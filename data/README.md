# Data

데이터 수집과 분산 처리 파이프라인을 관리합니다.

DE 와 DS 가 폴더를 나눠 쓰고, 폴더 사이는 코드가 아니라 **데이터 파일과 계약 문서**로 이어진다.

```
data/
├── docs/
│   ├── GIT_CONVENTION.md   파트 공통 브랜치·커밋·MR 규칙
│   └── contracts/          파트 사이 데이터 계약 (컬럼, 포맷, 위치)
├── de/     DE        — Kafka 컨슈머, HDFS 적재, 과거 CSV 변환
└── ds/     DS1 + DS2 — 파이썬 패키지 `hannun` 하나를 같이 만든다
    │         DS1: 중복 제거, 임베딩, 이슈 군집화 / DS2: 관점 대조
    └── docs/ds1/, docs/ds2/   개인 기록과 코드 규칙
```

## 데이터 흐름

```
BE 크롤러 ─Kafka─▶ DE ──공통 기사 JSON──▶ DS1 ──이슈 테이블──▶ DS2 ──관점 그룹──▶ BE 서빙 DB
                                              └──────────────────────────────────▶
```

| 계약 | 만드는 쪽 | 읽는 쪽 | 문서 |
|---|---|---|---|
| 공통 기사 JSON | DE (BE 스키마 그대로) | DS1 | BE 문서 §3 |
| 이슈 테이블 | DS (DS1) | BE | `docs/contracts/` (작성 예정) |
| 관점 그룹 | DS (DS2) | BE | `docs/contracts/` (작성 예정) |

DS1 과 DS2 사이는 같은 패키지 안이라 계약 문서 대신 코드(스키마 상수)로 맞춘다.

## 규칙

- 각 폴더는 소유자가 자기 스택으로 꾸린다. 실행법은 폴더 안 README 에 둔다.
- 다른 사람 폴더(`ds/` 안에서는 다른 사람 모듈)는 MR 리뷰 없이 고치지 않는다.
- 폴더 사이에 넘겨야 하는 게 생기면 코드를 import 하지 말고 `docs/contracts/` 에 계약을 먼저 쓴다.
- 브랜치·커밋은 [docs/GIT_CONVENTION.md](docs/GIT_CONVENTION.md).
