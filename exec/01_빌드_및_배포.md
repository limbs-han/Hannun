## 1-3. 배포 절차와 특이사항

### CI/CD 한 줄 요약

`develop` 머지 → GitLab 웹훅 → Jenkins 잡 `news-platform-deploy`(Pipeline from SCM, 브랜치 `*/develop`, 스크립트 `infra/Jenkinsfile`, 자격증명 `gitlab-token`) → 바뀐 폴더의 stage만 실행:
`back/**` → `back/deploy/deploy.sh`(블루그린) · `front/**` → `front/deploy/deploy.sh`(정적 rsync) · `data/**` → **echo만(미구현)**. DE·DS는 A에서 수동 `git pull`.
수동 "Build Now"는 changeset이 비어도 전 stage를 강제 실행한다.

### B 최초 구성 (한 번)

1. 호스트 패키지 (B의 apt 이력 그대로):
   ```bash
   # Docker 공식 저장소 (/etc/apt/keyrings/docker.asc, download.docker.com noble stable)
   sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin docker-buildx-plugin
   sudo usermod -aG docker ubuntu
   # nginx + Let's Encrypt
   sudo apt-get install -y nginx certbot python3-certbot-nginx
   sudo certbot --nginx -d j15e105.p.ssafy.io      # certbot.timer 가 자동 갱신
   # Jenkins (pkg.jenkins.io/debian-stable, /etc/apt/keyrings/jenkins-keyring.gpg) — 호스트 JDK 21 필요
   sudo apt-get install -y fontconfig openjdk-21-jre-headless
   sudo apt-get install -y jenkins                # systemd 서비스. 기본 8080 → 8089 로 바꾼다 (아래)
   sudo apt-get install -y unzip                  # Pinpoint 에이전트 압축 해제용
   # Jenkins 포트: /etc/systemd/system/jenkins.service.d/override.conf 에
   #   [Service]
   #   Environment="JENKINS_PORT=8089"
   sudo systemctl daemon-reload && sudo systemctl restart jenkins
   ```
   Jenkins는 `*:8089`로 모든 인터페이스에 열려 있지만 **외부에서는 차단됨**(2026-09-28 실측, 연결 안 됨). 접근은 nginx `:9443`(TLS)로만
2. `/home/ubuntu/news-platform/`에 `back/` 내용 복사. **git 리포가 아니다** — 여기 `deploy/*.yml`이 실제 인프라 정의이고 Pushgateway 추가도 여기에만 있다(`data/de/docs/monitoring.md`). 리포와 어긋날 수 있으니 바꿀 때 양쪽 갱신
3. `docker network create news-platform-net` → `docker compose -f deploy/docker-compose.infra.yml up -d`
   - MySQL 첫 기동 시 `docker/mysql/init/01-exporter-user.sql`(모니터링 계정) 자동 실행. **볼륨이 이미 있으면 안 돌아가므로 `docker exec`로 수동**
4. nginx: `sites-enabled/news-app`(443), `jenkins`(9443), `monitoring`(3443 Grafana, 8443 Kafka UI), `conf.d/news-app-upstream.conf`(deploy.sh가 덮어씀). 리포 `back/deploy/nginx-*.conf`를 복사한 뒤 certbot이 TLS 블록을 붙였다
5. `/var/www/news-front` 생성 후 `chown jenkins:jenkins`; `/etc/sudoers.d/jenkins-deploy` 3개 명령
6. Jenkins (실측 설정):
   - Credentials: GitLab 접근 토큰 → ID `gitlab-token`
   - 잡 `news-platform-deploy`: Pipeline script from SCM · Git `https://lab.ssafy.com/s15-bigdata-dist-sub1/S15P21E105.git` · 브랜치 `*/develop` · Script Path `infra/Jenkinsfile` · Lightweight checkout
   - Build Triggers: GitLab plugin — **push 이벤트만**(MR 이벤트 끔), 브랜치 필터 NameBasedFilter `develop`, Secret token 생성
   - GitLab 프로젝트 → Settings → Webhooks: URL `https://j15e105.p.ssafy.io:9443/project/news-platform-deploy`, 위 Secret token, Push events `[BE 확인: GitLab 쪽 등록 화면]`
   - Jenkins URL 설정 `https://j15e105.p.ssafy.io:9443/`
7. Pinpoint 에이전트 3.1.0을 `/home/ubuntu/pinpoint-agent/pinpoint-agent-3.1.0`에 압축 해제(collector 주소 A)
8. 첫 배포: `cd ~/news-platform/deploy && ./deploy.sh` → `.active_color` 생성(현재 `green`)

### 배포 특이사항 (겪은 것)

- **Airflow 컨테이너 재생성(`up -d`)은 실행 중 태스크를 죽인다.** DAG를 멈추고 실행 중인 것이 없을 때 한다. 재생성 후 웹서버가 120초 안에 못 뜨면 `rm -f /opt/airflow/airflow-webserver.pid` 후 재시작
- **이름 있는 볼륨을 붙일 경로는 이미지에 미리 만들어 둔다**(`/opt/airflow/state`, `/home/airflow/.ivy2`). 없으면 root 소유 빈 폴더가 생겨 쓰기가 막힌다
- **Kafka 토픽을 지우고 다시 만들면 DE 스트리밍 체크포인트가 깨진다**(`offsets are gone`). 재생성 전 DE에 알리고, DE는 체크포인트를 지운 뒤 재시작
- silver를 Iceberg로 읽는 잡(`bronze_to_silver`, `silver_to_ds_input`)은 `--packages …iceberg…1.9.1`이 있어야 한다. 같은 스크립트를 부르는 DAG마다 붙여야 한다
- HDFS UI(9870)·Airflow UI(8080)는 `127.0.0.1`에만 바인딩 — `ssh -L`로만 접속. Airflow는 DAG 실행 권한이라 공개 금지
- DS 컨테이너는 `-u 1000:1000` 없이 돌리면 산출물이 root 소유가 되어 이후 실행이 막힌다. `ds_chain`·`ds_assign`은 `flock /tmp/hannun_chain.lock`(10분 대기)으로 겹침을 막는다
- BE `spring.jpa.hibernate.ddl-auto=update` — 앱이 스키마를 자동 변경한다. 덤프 복원 뒤 컬럼 차이는 앱 기동 시 맞춰진다
- 블루그린 상태는 `~/news-platform/deploy/.active_color`. 헬스체크 실패 시 새 색상만 정리되고 기존은 유지
- `index.html`은 `no-cache`, `/assets/`는 1년 immutable — 재배포 후 옛 번들이 남는 문제 방지
- 시간대: A는 KST, B는 UTC. BE는 JDBC URL·Hibernate `time_zone`으로 KST를 명시했다
- 현재 silver는 파케이·Iceberg **양쪽에 쓰는 전환 중간 단계**다. 파케이 쓰기 중단(`SILVER_WRITE=iceberg`)과 옛 파케이 삭제가 남아 있다. Iceberg 스냅샷이 하루 약 1.8GB 늘어 정리(`expire_snapshots`) 필요
- 지표 전송은 B로 ssh해 컨테이너 IP로 보낸다(Pushgateway는 포트를 열지 않음). 실패해도 잡은 계속 간다
- **B의 관리 포트가 외부에 그대로 열려 있다** (2026-09-28 외부 실측): `:9090` Prometheus, `:8090` Kafka UI가 **로그인 없이** 응답한다(Kafka UI는 토픽 삭제까지 가능). `:3000` Grafana는 로그인 화면으로 넘어간다. compose가 호스트 포트를 매핑하고 보안그룹이 안 막고 있다. **보안그룹에서 3000·8085·8090·9090·9104·9121·9308을 닫고 nginx `:3443`(Grafana)·`:8443`(Kafka UI)만 남기는 것을 권장**. A의 Pinpoint `:8090`도 같다
