# 4. 시연 시나리오

서비스 이름 **한눈**. 뉴스를 이슈로 묶고, 이슈 안에서 언론사별 관점(긍정·중립·부정)과 공통 사실을 한눈에 보여준다.
접속 `https://j15e105.p.ssafy.io`. 화면은 Vue 단일 페이지(`front/src/App.vue`)다.

화면 요소 이름은 코드의 문구를 그대로 썼다. 배치(`App.vue` 템플릿 순서): **상단** 로고 버튼("한눈 홈으로 이동") · 검색 버튼 → 검색 패널(입력창, 관련 검색, 최근 검색어) → **분야 탭 줄**(`nav`) → **본문** 소개(`hero`) → 이슈 피드(`feed`: 정렬 버튼 "화제성순"·"최신순", 기간 필터, 캘린더, "더 보기") → 이슈 상세(`detail`: 브리핑 → 관점 `view` → "의견 더 보기"·"보도 더 보기") → **인기 검색어**(`aside.trends`) → 검색 결과(`results`, 검색 상위 이슈).

## 0. 시연 전 점검 (10분 전)

| 확인 | 명령·위치 | 정상 |
|---|---|---|
| 서비스 응답 | `curl -s -o /dev/null -w "%{http_code}" "https://j15e105.p.ssafy.io/api/issues?category=ALL&sort=trending"` | 200 (`category` 없이 부르면 400이 정상) |
| B 컨테이너 | B에서 `docker ps` | `news-app-<색상>-1/2`, mysql, redis, kafka×3 Up |
| 최근 발행 | Airflow UI(터널 `localhost:8080`) → `ds_daily` 마지막 실행 | 최근 15분 안 성공 |
| 수집 | Airflow → `crawl_publish`, `article_ingest` | 최근 15분 안 성공 |
| 지표 | Grafana `https://j15e105.p.ssafy.io:3443` → `DE 파이프라인` 대시보드 | 그래프가 오늘 시각까지 이어짐 |

알려진 차이: FE가 사용 로그를 `POST /api/logs`로 보내는데 BE에 그 경로가 없어 **404**다(2026-09-23 확인). 화면 동작에는 영향이 없다. 시연 중 브라우저 콘솔을 열면 보이니 열지 않는다. `[BE·FE 확인: 엔드포인트 추가 또는 호출 제거]`

문제가 있으면 시연은 **화면만** 진행한다. DB에 이미 쌓인 이슈로 화면은 동작하고, 뒷단 시연(6장)만 뺀다.

## 1. 홈 — 오늘의 이슈

| 순서 | 조작 | 기대 화면 | 뒤에서 |
|---|---|---|---|
| 1-1 | `https://j15e105.p.ssafy.io` 접속 | "화제성 높은 이슈" 카드 목록. 카드마다 제목·분야·"N개 언론사 · 관련 기사 M건" | `GET /api/issues?category=ALL&sort=trending` → `{items, nextCursorValue, nextCursorId, hasNext}` |
| 1-2 | 상단 분야 탭 **정치** 클릭 | 정치 이슈만 남음 | `GET /api/issues?category=정치&sort=trending` (분야는 한글 값 그대로, 전체만 `ALL`) |
| 1-3 | 정렬을 **최신순**으로 | 최근 묶인 이슈가 위로 | `…&sort=latest` |
| 1-4 | 아래로 스크롤 | 다음 페이지가 이어서 붙음 | `hasNext`면 `cursorValue`·`cursorId`를 붙여 다시 호출 |

**말할 것**: 카드 하나가 이슈 하나. 여러 언론사 기사를 우리가 자동으로 묶은 결과다. 화제성 점수는 언론사 수·기사 수·최신성으로 계산한다.

## 2. 기간 선택

| 순서 | 조작 | 기대 화면 | 뒤에서 |
|---|---|---|---|
| 2-1 | 기간 선택(캘린더) 열기 | 달력. "이전 달"·"다음 달" 이동 | 화면 내 처리 |
| 2-2 | 시작·끝 날짜 클릭 후 적용 | 그 기간의 이슈만 표시 | `GET /api/issues/date-range?category=ALL&sort=trending&from=YYYY-MM-DD&to=YYYY-MM-DD` (+cursor) |
| 2-3 | 끝이 시작보다 앞이면 | 오류 문구(`dateRangeError`) | 화면에서 막음 |

## 3. 검색

| 순서 | 조작 | 기대 화면 | 뒤에서 |
|---|---|---|---|
| 3-1 | 검색창(placeholder "이슈, 키워드 검색") 클릭 | **인기 검색어**와 최근 검색어 펼침 | `GET /api/search/suggestions` — `news.search.executed` 토픽을 BE가 집계한 인기 검색어 |
| 3-2 | "북미회담" 타이핑 | 입력 중 미리보기 결과 | `GET /api/search?keyword=북미회담&preview=true` (분야 탭이 전체가 아니면 `&category=정치`) |
| 3-3 | Enter | "'북미회담' 검색 결과" 목록 | `GET /api/search?keyword=북미회담&preview=false` (+cursor) → BE가 `news.search.executed` 발행 → 인기 검색어 갱신 |
| 3-4 | 최근 검색어 옆 삭제(×) | 항목 제거 | 브라우저 저장 |

**말할 것**: 같은 사건이 결과에 한 번만 나온다. 날짜가 바뀌어도 어제 이슈 번호를 이어받게 고쳐서(9/21) 중복이 쌓이지 않는다.

## 4. 이슈 상세 — 핵심

| 순서 | 조작 | 기대 화면 | 뒤에서 |
|---|---|---|---|
| 4-1 | 카드 클릭 | 상세 화면. 제목, 분야, **공통사실 브리핑**(문장 2~3개) | `GET /api/issues/{issueId}?stance=neutral&page=0` (첫 진입 성향은 화면이 정함, 없으면 다른 성향으로 자동 대체) |
| 4-2 | **관점 선택** — 긍정 · 중립 · 부정 | 선택한 성향의 관점 그룹 목록. 각 그룹에 라벨·미리보기 기사 | 같은 주소에 `stance=positive｜neutral｜negative` → 응답 `viewpointGroups[].previewArticles` |
| 4-3 | 비율 공개(있으면) | 성향별 기사 비율 % 표시(`hasRevealedRatio`) | 응답 `stanceRatio`(이슈 전체 값, 탭을 바꿔도 첫 응답을 유지) |
| 4-4 | 관점 그룹 하나 클릭 | **관련 주요 뉴스** — 그 그룹의 기사 목록(언론사·제목·링크) | `GET /api/issues/{issueId}/viewpoint-groups/{groupId}/articles` (+`cursorPublished`,`cursorArticleId`) |
| 4-5 | 기사 클릭 | 언론사 원문으로 이동(새 탭) | 외부 링크 |

**말할 것**: 브리핑은 서로 다른 언론사 두 곳 이상이 같이 쓴 문장만 고른 것이다. 한 곳만 말한 건 빼서 "사실"에 가깝게 한다. 관점 그룹은 같은 성향 안에서도 논점이 다르면 나눈다.

**주의**: 관점 라벨이 "기타 관점"으로 나오는 이슈가 많다(9/21 기준 약 7할). 시연 이슈는 **라벨이 붙은 것**을 미리 골라 둔다(홈 상위 카드 중 기사 10건 이상인 정치·경제 이슈가 안전). 브리핑이 비면 대표 기사 앞부분이 대신 들어간다.

## 6. 뒷단 시연 (선택, 3분)

화면에 안 보이는 처리량을 보여줄 때. 노트북에서 `ssh a`로 터널을 미리 연다.

| 순서 | 열 것 | 보여줄 것 | 말할 것 |
|---|---|---|---|
| 6-1 | Airflow `http://localhost:8080` (관리자 비밀번호는 A의 `standalone_admin_password.txt`) | DAG 8개 격자. `crawl_publish`·`article_ingest` 15분마다 초록 | 13개 언론사 92개 피드를 15분마다 수집해 Kafka로 보내고, Spark가 HDFS 레이크에 쌓는다. 누적 기사 약 1,115만 건 |
| 6-2 | `article_ingest` → 최근 실행 → 그래프 | `kafka_to_bronze → bronze_to_silver → silver_to_ds_input` | 원본(bronze) → 정제(silver, Iceberg 테이블) → 분석 입력(ds_input) 세 계층 |
| 6-3 | `ds_chain`(매시) · `ds_assign`(15분) | DS 체인 실행 | 중복 제거 → 임베딩 → UMAP+HDBSCAN 군집 → 이슈 번호 승계 → 관점 분석. 매시 재군집, 사이사이 새 기사 배정 |
| 6-4 | `ds_daily` → `publish_clustering` 로그 | "이슈 N개, 기사 M건, 어제 번호 이어받음 K개" | 이슈 피드를 Kafka로 발행해 BE가 받는다 |
| 6-5 | Grafana `https://j15e105.p.ssafy.io:3443` (nginx `monitoring`이 :3000으로 프록시, 계정은 compose `GF_SECURITY_ADMIN_*`) → 대시보드 "DE 파이프라인" | 위 두 줄 양(적재·발행 건수), 아래 두 줄 질(관점 실패율·중립 쏠림·브리핑 폴백·최대 이슈 크기) | 처리량뿐 아니라 결과의 질을 매 실행 잰다. 라벨이 깨진 걸 3주 뒤에 알았던 경험에서 붙였다 |
| 6-6 | (여유 있으면) Kafka UI `https://j15e105.p.ssafy.io:8443` (nginx `monitoring`이 :8090으로 프록시) → 토픽 `news.clustering.completed` | 메시지 누적 8만 건+, 파티션 3·복제 3 | key가 clusterId라 같은 이슈는 갱신으로 처리. 실패분은 `-dlt` 토픽으로 |
| 6-7 | (여유 있으면) Pinpoint A `:8090` | 앱 두 인스턴스의 요청 흐름 | BE 응답 시간 추적 |

## 7. 질문 대비 한 줄 답

| 질문 | 답 |
|---|---|
| 데이터 규모 | 기사 1,115만 건(2019~), 하루 약 2,500건 수집, 이슈 하루 250~400개 |
| 언론사 | 13사 92개 RSS. 화면 로고는 11사 |
| 왜 Iceberg | 파일 목록을 테이블이 관리해 증분 판정이 2배 빨라졌고, 쓰다 죽어도 반쪽 상태가 안 남는다. 운영 중단 없이 양쪽 쓰기 → 읽기 전환 → 검증(1,115만 건 일치)으로 옮겼다 |
| 관점 라벨이 "기타"인 이유 | 규칙 기반 추출기가 8자 제한·52개 단어 목록을 못 넘으면 기타로 떨어진다. 원인 측정을 끝내 DS에 넘겼고, 그룹 번호를 함께 내보내는 수정이 우선순위 1이다 |
| 중복 이슈 | 날짜가 바뀔 때 새 번호가 나던 문제. 발행 직전에 어제 번호로 되돌려 막았다(승계 성공률 73% → 발행 기준 중복 0) |
| 장애 시 | 블루그린이라 헬스체크 실패 시 기존 색상 유지. 데이터는 새벽 B 백업 60일 |
